HTML 转链接：把本地 HTML 文件变成可分享的网址

不用服务器、不用部署、不用备案。拖一个 .html 文件进去，拿一条 https 链接，发给谁都能打开。

Plain 是 MIT 开源项目。 这一页讲的是怎么自己跑（本地部署、接进 AI agent）； 如果你只想拖一个文件拿条链接，直接用托管版更快：

打开在线版 →

这个需求的几种说法

同一件事有很多种叫法 —— HTML 转链接、HTML 转 URL、HTML 转网址、HTML 文件转链接、 HTML 转在线链接、HTML 网页转链接、本地 HTML 转在线网页。 说的都是同一个动作：手上有一个做好的 HTML 文件，想让别人点开就能看。

传统做法要么买服务器传上去，要么用 GitHub Pages / Vercel 配一遍仓库和构建， 要么发文件让对方下载（微信里发 .html 对方多半打不开）。 这三条路对「我就想发个课件给学生」来说都太重了。

方式一：在线拖拽（最快）

打开 inplain.app/zh/html-to-url， 把文件拖进去，链接立刻就有了。不登录也能用，匿名链接保留 7 天；登录后长期保留。

方式二：让 AI agent 生成并发布

Plain 同时是一个 MCP 服务器。 接进 Claude Code、Cursor 或其他支持 MCP 的 agent 后， agent 可以直接生成 deck / doc / sheet 并发布成链接交回来： 

npm install -g @inplain/cli
plain install    # 自动写入 Claude Code / Cursor / VS Code 的配置

然后在 agent 里直接说「读一下这个目录，做一份八页的汇报 deck」， 它会把成品和链接一起给你。

⚠️ 这条路是让 agent 从头生成内容。 如果你手上已经有一个做好的 .html 文件， 目前只能用上面的在线拖拽 —— 命令行的 plain push 只接受 Markdown 源文件， 还不支持直接上传 HTML。

各种做法的对比

做法要准备什么适合
在线拖拽 什么都不用 偶尔发一两个
MCP 接进 agent 一条 plain install 让 AI 生成并直接发布
GitHub Pages 仓库 + 分支 + 等构建 长期维护的站点
自己买服务器 服务器 + 域名 + 备案 完全自控

常见问题

带 JavaScript 的互动网页能转吗？
能。单文件里的 JS、CSS、动画都原样保留，所以互动课件、知识闯关、配对卡牌、 物理仿真这类可点击的页面都能正常跑。
要买服务器或域名吗？
不用。链接直接托管，微信、QQ、钉钉里都能打开。
链接能存多久？
匿名 7 天，登录后长期保留。也可以自己部署做永久托管 —— 代码是 MIT 的。
图片和字体要单独传吗？
内联的（base64、CDN 链接、Web Font）不用管。 但如果 HTML 里引用的是 ./img/x.png 这种本地相对路径， 那些文件不会跟着一起上传，发布后会显示不出来 —— 先把它们内联进单文件。
文件来自 AI 生成的，要注意什么？
发布前先在本地打开看一遍：检查有没有写死的密钥、有没有引用本地路径、 内容事实对不对。发布后用无痕窗口再验证一次链接。

自己跑

git clone https://github.com/io-oi-ai/inplain
cd inplain
pnpm install
pnpm plain --help

渲染管线在 packages/core，是纯函数 —— 不碰网络、不依赖框架， 可以单独当库用。
