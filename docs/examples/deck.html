The problem

An agent that edits documents is only as reliable as its ground truth.

01
Binary blobs hide meaning
An agent cannot see intent inside a .docx — it sees XML noise. Every edit is a guess mapped through a parser that was not built for reasoning.
0
visibility into structure
02
Each view forks reality
The doc says one thing, the deck says another, the sheet says a third. Three sources of truth means three sources of lies.
3
competing states
03
An agent's edit is a black box
Without a readable source, you cannot diff — you cannot trust. So the human re-reads everything, and the point of having an agent collapses.
100%
human re-verification
The fix

Plain text is the one format an agent can hold in its working memory.

1
No more parsers
An agent reads a Plain file and sees exactly what a human sees — headings, cells, slides as typed structure. No speculation about what the file 'means'.
2
Diffs are honest
A Plain source diffs line-by-line. The agent's edit is a visible, reviewable change — not a blob swap.
3
Rendered views are derived
Deck, doc, sheet are generated from the same source. Edit once, see it everywhere — with no sync step to forget.

One model, three views

D

Under the hood

How Plain keeps views in sync

  1. Edit
    One edit to the Plain source
    a cell changes, a heading moves, a list grows
  2. Derive
    Each view recomputes from source
    no stored state in the view — only the source is authoritative
  3. Verify
    Diff shows exactly what changed
    human or agent can inspect the line-level delta before accepting

Plain vs. traditional files

Traditional (docx + pptx + xlsx)
  • Three separate files with separate formats
  • Agent must parse binary XML to reason
  • Edits are opaque — cannot trust without re-reading
  • Sync between views is manual and always late
Plain
  • One plain-text source file
  • Agent reads the same structure a human does
  • Every edit is a reviewable line-diff
  • Deck, doc, sheet are derived, never divergent
